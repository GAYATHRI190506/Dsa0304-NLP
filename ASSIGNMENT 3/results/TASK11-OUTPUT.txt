================================================================================
QUALITATIVE COMPARISON
================================================================================

--- Correctness / Coverage ---

Top-Down:
  Good for simple CFG sentences, but direct left recursion must be controlled or eliminated.

Earley:
  Strong CFG coverage and can handle left recursion and ambiguous structures.

Viterbi:
  Provides the best parse under a probabilistic model, but the CKY-style implementation requires suitable grammar form.

--- Ambiguity Handling ---

Top-Down:
  Can generate multiple parses, but ambiguity can increase search and backtracking.

Earley:
  Naturally represents multiple analyses using chart states and packed-style structures.

Viterbi:
  Ranks competing parses using probabilities and selects the highest-scoring analysis.

--- Runtime / Space ---

Top-Down:
  Simple and lightweight for small unambiguous grammars, but recursive search can become expensive.

Earley:
  Uses chart parsing to avoid repeated work. Worst-case CFG complexity is O(n^3).

Viterbi:
  Dynamic programming avoids repeated subproblems and is efficient for CNF-style grammars.

--- Ungrammatical Input ---

Top-Down:
  Rejects input when no complete derivation is found, but recursive search must be controlled.

Earley:
  Rejects input when the completed start state is absent from the final chart.

Viterbi:
  Rejects input when no valid complete probabilistic parse is available.

--- Extension / Maintenance ---

Top-Down:
  Easy to understand and modify for small grammars.

Earley:
  More complex implementation but highly flexible for CFG extensions.

Viterbi:
  Good when probabilities and ranking are required, but grammar conversion and probability estimation add complexity.

================================================================================
ADVANTAGES AND LIMITATIONS
================================================================================

-------------------- Top-Down --------------------

Advantages:
  + Simple recursive implementation.
  + Easy to understand and debug.
  + Useful for small deterministic grammars.
  + Can produce explicit parse trees.

Limitations:
  - Left recursion can cause infinite recursion.
  - Backtracking can increase runtime.
  - Ambiguity may produce many alternative parses.
  - Performance decreases for complex grammars.

-------------------- Earley --------------------

Advantages:
  + Handles general context-free grammars.
  + Supports left-recursive grammar rules.
  + Works well with ambiguous structures.
  + Uses chart states to avoid repeated work.

Limitations:
  - Implementation is more complex.
  - Can require more memory than simple parsing.
  - Worst-case complexity is O(n^3).

-------------------- Viterbi --------------------

Advantages:
  + Ranks parses using probabilities.
  + Selects the most probable interpretation.
  + Dynamic programming reduces repeated computation.
  + Useful for ambiguity resolution.

Limitations:
  - Requires a probabilistic grammar.
  - Probabilities depend on training data.
  - CKY-style parsing normally requires CNF/binary rules.
  - Rare or unseen constructions may receive zero probability.

================================================================================
RECOMMENDATION FOR UNIVERSITY HELPDESK
================================================================================

Recommended architecture:

1. Earley Parser
   Use Earley parsing as the main syntactic parser.

   Reason:
   - Handles general CFGs.
   - Supports recursion.
   - Handles ambiguous structures.
   - Provides chart states that can be inspected.
   - Suitable for complex university-helpdesk queries.

2. Feature Structures
   Combine Earley parsing with feature structures
   for agreement, number, person, case and
   subcategorization constraints.

3. PCFG / Viterbi
   Use probabilistic ranking after generating
   candidate parses.

   This is useful when a sentence has multiple
   structurally valid interpretations.

4. Top-Down Parsing
   Keep Top-Down parsing mainly as a simple
   baseline/reference parser.

Overall recommendation:

    Earley + Feature Structures + PCFG Ranking

This combination provides a balance between:

    grammatical coverage
    ambiguity handling
    linguistic constraints
    robustness
    probabilistic ranking
    maintainability
